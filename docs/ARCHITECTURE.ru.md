# Архитектура

mimic — система из трёх слоёв. Каждый слой — отдельный компонент со стабильным интерфейсом, чтобы слои можно было заменять независимо: подменить Claude на локальную модель, заменить C++ захват на Python fallback, добавить новый таргет без правок в захват или vision.

```
┌──────────────────────────────────────────────────────────────┐
│                  Слой 3: Десктоп UI на Flutter               │
│  Управление записью · live preview · редактор кода · экспорт │
└─────────────────────────┬────────────────────────────────────┘
                          │ FFI / локальный IPC
┌─────────────────────────▼────────────────────────────────────┐
│                  Слой 2: Python-оркестратор                  │
│  Vision API · сборка дерева виджетов · генераторы кода · CLI │
└────────────┬─────────────────────────────────┬───────────────┘
             │ pybind11                        │ HTTP / SDK
┌────────────▼────────────┐         ┌──────────▼───────────────┐
│   Слой 1: Нативный C++  │         │   Vision-провайдер       │
│   Захват экрана         │         │   (Claude · GPT-4V ·     │
│   DXGI · AVFoundation · │         │    локальный Florence/   │
│   PipeWire · дедуп      │         │    Llava)                │
└─────────────────────────┘         └──────────────────────────┘
```

## Слой 1: Нативное ядро захвата (`native/`)

Написан на C++20. Единственная задача — отдать кадры в Python максимально быстро, не нагружая CPU. Платформо-специфичные реализации за одним C ABI.

- **Windows** — `IDXGIOutputDuplication` для захвата без разрывов, копия в staging-текстуру, отдача в виде сырого BGRA.
- **macOS** — `ScreenCaptureKit` (macOS 12.3+), fallback на `CGDisplayStream` для старых версий.
- **Linux** — портальное API `PipeWire` (натив для Wayland, X11 через XCB shm fallback).

Критичные оптимизации в C++ до перехода кадров в Python:

1. **Дедупликация кадров** — перцептивный хэш + ранний reject если расстояние `dhash` ниже порога. Срезает ~95% кадров в типичной записи.
2. **Регион интереса** — когда пользователь записывает одно окно, остальное маскируется.
3. **Оверлей курсора/кликов** — синтетический курсор с событиями кликов рисуется поверх кадра, чтобы vision-модель могла понять "куда тыкал пользователь" без отдельного потока событий.

Python получает кадры через биндинги `pybind11` как `numpy.ndarray`.

## Слой 2: Python-оркестратор (`python/`)

Мозг. Принимает кадры (или одиночные скриншоты), анализирует UI, выдаёт код.

Пайплайн:

```
кадры ─► дедуп ─► сегментация ─► дерево виджетов ─► codegen ─► файлы
                       │                  │
                       └─► vision API ◄───┘
```

- **Vision-адаптеры** (`vision/`) — общий интерфейс, конкретные бэкенды для Claude / OpenAI / локальных. Каждый бэкенд возвращает структурированное `WidgetTree` (Pydantic-модель), а не сырой текст. Модели промптятся со строгой JSON-схемой, чтобы получать структуру.
- **Сегментация** — если на входе видео, идентифицируются устойчивые UI-состояния по кадрам (кластеризация по перцептивному хэшу) и переходы помечаются как интеракции.
- **Генераторы кода** (`codegen/`) — каждый целевой фреймворк это функция `WidgetTree → SourceFile[]`. Генераторы pure: то же дерево на входе → тот же код на выходе. Никакого I/O внутри генераторов.
- **CLI** — `mimic gen`, `mimic record`, `mimic ui` это тонкие обёртки над пайплайном.

## Слой 3: Десктоп UI на Flutter (`ui/`)

Кросс-платформенное десктоп-приложение (Windows / macOS / Linux). Подключается к оркестратору по локальному IPC (по умолчанию: 127.0.0.1:54321, JSON-RPC). Три основных экрана:

- **Capture** — выбор области, запись / стоп, переключатель таргет-фреймворка.
- **Preview** — split-view: слева отрисованный preview сгенерированного UI, справа исходник с подсветкой и inline-редактированием.
- **Library** — недавние записи и их артефакты, сгруппированные по проектам.

UI намеренно тонкий. Вся логика в Python — Flutter это окно в пайплайн. Это позволяет headless / CI использовать тот же backend.

## Почему такой выбор технологий

| Решение                        | Причина                                                       | Что рассматривалось              |
| ------------------------------ | ------------------------------------------------------------- | -------------------------------- |
| C++ для захвата                | Суб-мс на кадр, нативные zero-copy пути                       | Rust (похожая перф, меньше экосистема) |
| Python для оркестрации         | Vision SDK живут здесь, скорость прототипирования             | Go / Rust (хуже для ML-итерации) |
| Flutter для UI                 | Одна кодовая база, нативная производительность, совпадает с таргетом | Electron (тяжёлый), Tauri (менее зрелый) |
| JSON-RPC поверх локального TCP | Flutter-приложение независимо от языка и отделимо             | Прямой FFI (теснее связь)        |
| Сменный vision-провайдер       | Без вендор-лока, возможность local-first                      | Один провайдер (проще, но хрупко) |

## Поток данных: 15-секундная запись

1. Пользователь жмёт Record во Flutter-приложении.
2. Flutter отправляет `start_recording` через JSON-RPC.
3. Python зовёт нативный код через pybind11 — кадры идут в ring buffer.
4. Нативный дедуп выбрасывает ~95% кадров; оставшиеся ~5 fps идут в Python.
5. Python сегментирует запись на ~3-5 различимых UI-состояний.
6. Для каждого уникального состояния vision API возвращает `WidgetTree`.
7. Переходы между состояниями аннотируются интеракциями (`onTap`, `onScroll`, и т.д.).
8. Flutter-codegen обходит дерево → пишет `lib/screens/*.dart`, `lib/widgets/*.dart`, `lib/main.dart`.
9. Файлы появляются в превью UI; пользователь может редактировать перед экспортом.

Целевая end-to-end задержка для v0.2: меньше 10 секунд на 15-секундный клип на обычном лэптопе.

## Что НЕ делаем

- Мы не пытаемся заменить Figma. mimic генерирует код из наблюдаемого UI, а не из дизайн-намерения.
- Мы не генерируем приложения целиком. mimic генерирует UI-скелет; бизнес-логика, роутинг и слой данных всё ещё на тебе.
- Мы не записываем аудио или нажатия клавиш (кроме того, что отображается в UI). Приватность и скоуп.
